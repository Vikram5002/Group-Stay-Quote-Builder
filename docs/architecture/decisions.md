# Decision log

Every scope or design decision, with date and reason. Architecture decision records ADR 1 to 10 live in the master blueprint, section 7.3; entries here refine or add to them.

| ID    | Date       | Decision                                                                                                                                                                                                                                                   | Reason                                                                                                                                                                                      |
| ----- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-001 | 2026-10-17 | Floor mode defaults to `absolute` (20000, from the fixture). `per_room_night` uses its own field `floor_per_room_night_inr` (default 1000).                                                                                                                | Matches the fixture field. A separate field keeps one meaning per field. Under an absolute floor small groups and partial cancellations always need review; open question 1 to case owners. |
| D-002 | 2026-10-17 | Add `min_validity_hours` to the policy, default 2 (HYPOTHESIS).                                                                                                                                                                                            | The validity rule (blueprint 5.7) uses it, but the policy entity, table item and assumption register omitted it. Recorded as assumption A13.                                                |
| D-003 | 2026-10-17 | Pin TypeScript to `~6.0`.                                                                                                                                                                                                                                  | typescript-eslint supports TypeScript below 6.1 only; TypeScript 7 is not yet supported.                                                                                                    |
| D-004 | 2026-10-17 | Generate OpenAPI 3.1 with Zod 4's native `z.toJSONSchema`, not a third-party generator.                                                                                                                                                                    | One fewer dependency; OpenAPI 3.1 uses JSON Schema 2020-12 natively. Route metadata lives in a typed `ROUTES` table that the API will also use.                                             |
| D-005 | 2026-10-17 | `stay` accepts `nights`, `check_out` or both; they must agree.                                                                                                                                                                                             | Supports CSV and calendar input; makes test T08 (check-out before check-in) expressible.                                                                                                    |
| D-006 | 2026-10-17 | Add error codes `IDEMPOTENCY_CONFLICT` (409), `PAYLOAD_TOO_LARGE` (413), `UNSUPPORTED_MEDIA_TYPE` (415). Malformed JSON is 422 with `INVALID_JSON`.                                                                                                        | Every response stays problem+json with a stable code, including body-parser failures.                                                                                                       |
| D-007 | 2026-10-17 | Approval moves a quote from `PENDING_REVIEW` to `OFFERED`, with the approval bound to the terms hash. Amendments and extensions keep the status.                                                                                                           | Makes BR-10 a single rule: only `OFFERED` quotes confirm.                                                                                                                                   |
| D-008 | 2026-10-17 | `data/fixtures/fixture.json` is kept verbatim. A documented, tested transform in `@c32/core` maps it into domain inputs.                                                                                                                                   | The README requires the fixture schema to stay authoritative and any mapping to be explicit and tested.                                                                                     |
| D-009 | 2026-10-17 | One branch per work package (`T1.01`), merged into `main` without pull requests.                                                                                                                                                                           | Team working agreement; see .github/CONTRIBUTING.md.                                                                                                                                        |
| D-010 | 2026-10-17 | Replace per-work-package branches with one branch per track (`T1` to `T4`); each finished work package gets a tag (`T1.01`, `T1.02`, ...). Supersedes the branch part of D-009.                                                                            | Mentor's guidance: one track branch holds all its phases in order; tags keep each phase findable.                                                                                           |
| D-011 | 2026-10-17 | Contribution margin is contribution over total revenue (room revenue plus separately charged inclusions).                                                                                                                                                  | With no separate charges it equals the blueprint formula; with them (T19) the blueprint quotes total revenue 48000, so the margin must use the same base. Display only.                     |
| D-012 | 2026-10-17 | The minimum safe rate is a flat room rate, rounded up (BR-20), never below 0, and still computed when the quoted rate is unknown. It is unknown when any cost or the extras revenue is unknown, or there are no room-nights.                               | Tells the sales manager what to charge even before a rate is set; a negative rate is meaningless.                                                                                           |
| D-013 | 2026-10-17 | Pricing accepts generic package extras (revenue and cost) that T1.05 will fill from the inclusions model.                                                                                                                                                  | Keeps T1.02 free of inclusion rules while the formula, floor and minimum rate already account for them.                                                                                     |
| D-014 | 2026-10-17 | Time zone maths uses the runtime's built-in IANA database (`Intl`) instead of a date library.                                                                                                                                                              | Node and every modern browser ship the full database; one fewer dependency in core, and tests cover IST, UTC and DST zones.                                                                 |
| D-015 | 2026-10-17 | A quote is expired from the `valid_until` instant onward (the boundary instant is expired), and a validity window exactly equal to `min_validity_hours` is still allowed.                                                                                  | One unambiguous comparison each, both tested at the millisecond.                                                                                                                            |
| D-016 | 2026-10-17 | Rules read time only through an injected `Clock`; tests use `fixedClock` or `ManualClock`.                                                                                                                                                                 | Expiry (T15, T25) and the demo's clock fast-forward become deterministic.                                                                                                                   |
| D-017 | 2026-10-17 | Unknown pricing inputs raise reason codes (`UNKNOWN_RATE`, `UNKNOWN_COST`) in catalogue order; T1.04's decision engine maps any reason to REVIEW, which completes T06.                                                                                     | Keeps the null policy separate from the decision logic and gives stable, testable output.                                                                                                   |
| D-018 | 2026-10-17 | A night with no inventory row means DECLINE with `NO_INVENTORY_DATA` (the night is not on sale). A missing night outranks an unknown one.                                                                                                                  | The blueprint allows DECLINE or REVIEW "per policy" but defines no policy field; "not on sale" is the literal reading and never over-sells. Revisit if owners want REVIEW.                  |
| D-019 | 2026-10-17 | PARTIAL_OFFER means "short of rooms, otherwise clean". A partial that also breaches the floor or has an unknown value is REVIEW, keeping `PARTIAL_AVAILABILITY` among its reasons.                                                                         | Fixes review finding 5: a floor-breaching partial must reach the owner's queue, not look like a clean offer. This makes T10 depend on the floor mode (see D-020).                           |
| D-020 | 2026-10-17 | T10 (10 then 8 rooms, request 12) is tested in both floor modes: per room-night gives PARTIAL_OFFER for 8; the absolute 20000 floor gives REVIEW because 8 rooms earn 19200.                                                                               | The blueprint's expected value ignores the floor. Evidence that floor semantics (question 1 for the case owners) changes outcomes, not just numbers.                                        |
| D-021 | 2026-10-17 | Until the inclusions model lands (T1.05), any inclusion on a request makes extras unknown, so the quote goes to REVIEW with `UNKNOWN_COST`.                                                                                                                | Never silently ignore a cost such as breakfast (blueprint 5.6).                                                                                                                             |
| D-022 | 2026-10-17 | A DECLINE prices zero rooms and carries only its decline reason; pricing reasons are not added.                                                                                                                                                            | A declined quote has no package to judge against the floor; reporting `FLOOR_BREACH` there would mislead.                                                                                   |
| D-023 | 2026-10-17 | Inclusions are priced for the offered rooms; guests per room come from the request, else the policy default; unknown guests or unit cost make the cost unknown (REVIEW). Supersedes D-021.                                                                 | Blueprint 5.6 and the null policy: never assume one guest or a free breakfast.                                                                                                              |
| D-024 | 2026-10-17 | A counter-offer is kept only if the same engine re-evaluates it as a clean OFFER, and its contribution is reported from that re-run.                                                                                                                       | Guarantees every suggestion is floor-safe and within capacity (FR-12), with no second implementation of the rules.                                                                          |
| D-025 | 2026-10-17 | REPRICE_INCLUSION proposes charging a bundled inclusion separately at its unit cost.                                                                                                                                                                       | Cost-neutral is the smallest change that is always floor-safe; the sales manager can charge more. The blueprint's 200 INR price is one example of this lever.                               |
| D-026 | 2026-10-17 | Counter-offers are ranked PARTIAL_ROOMS, RAISE_RATE, REPRICE_INCLUSION, CHANGE_VOLUME; CHANGE_VOLUME is the fewest extra rooms within sellable inventory. None are generated when a value is unknown or for a DECLINE; ALT_DATES (COULD) is not generated. | Least disruptive first; unknown values cannot be proven safe.                                                                                                                               |
