# Growth experiment: pitch to a fictional event organiser (T4.06)

Tests H6: _organisers respond faster, and more decisively, to a dated, itemised quote than to a
typical manual reply_ (blueprint 16.6).

**Honesty rule:** results from role-play are **process evidence, not market demand**. The
report must say so, and negative results are recorded too.

## Design

| Element                   | Choice                                                                                                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Participants              | At least 4 classmates or mentors, each playing a corporate or wedding organiser, with consent                                           |
| Groups                    | A/B split: half receive Offer A (tool), half Offer B (manual), then swap with a new enquiry                                             |
| Offer A                   | [`offer-a-tool.md`](../../evidence/experiment/offer-a-tool.md): itemised, dated, held until a stated time, generated by the live system |
| Offer B                   | [`offer-b-spreadsheet.md`](../../evidence/experiment/offer-b-spreadsheet.md): approximate, no dates, no validity                        |
| Channel                   | Email or chat, the same for both offers                                                                                                 |
| Brief to each participant | "You are organising a 2-night December offsite for 10 rooms with breakfast. Reply to the hotel as you would in real life."              |
| Primary measure           | Minutes to first response                                                                                                               |
| Secondary                 | Outcome tier reached; number of clarifying questions                                                                                    |

## Outcome tiers (blueprint 16.6)

| Tier | Meaning                                   |
| ---- | ----------------------------------------- |
| 1    | Replied                                   |
| 2    | Asked for a change (counts as engagement) |
| 3    | Accepted in the simulation                |
| 4    | Asked how to get it for a real event      |

## Procedure

1. Get consent (the discovery plan's script, adapted). Record no names: use `ORG-01`, `ORG-02`.
2. Send the assigned offer; note the time (IST).
3. Answer follow-ups as the hotel would. If a change is asked for, re-quote with the tool and
   note the new quote in `notes`.
4. Stop after 48 hours or at tier 3 or 4.
5. Fill one row per contact in [`evidence/experiment/log.csv`](../../evidence/experiment/log.csv).

## Analysis (after the runs)

- Median minutes to first response, A vs B.
- Share reaching tier 2 or higher, A vs B.
- Clarifying questions per contact (B is expected to need more: dates, totals, validity).

With 4 to 8 role-play contacts the difference is **indicative only**: no statistical claim.
Record the result in the ledger as E07 with type "Observed (role-play)".
